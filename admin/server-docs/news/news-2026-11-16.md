# BuildEngine News — 2026-11-16

## DNG JPEG XL XMP guard

- The DNG producer reached a native C++ compile error in `dng_jxl.cpp:1540`: `dng_metadata` exposes no `GetXMP()` while `qDNGUseXMP=0`.
- Added a version-bound source patch around the XMP-box serialization block only, with the standard check/apply/reverse-check actions. EXIF, IPTC and JPEG XL support are preserved.
- Advanced the DNG logical source timestamp. **[not verified]** Post-correction BCC64X Release and Debug builds and runtime acceptance remain pending.

## DNG CMake module scanning correction (16 November 2026)

- Release and Debug reported a fatal missing `sdks/_mingw_ddk.h` include while CMake generated `dng_globals.cpp.o.ddi` for module dependency scanning. The compiler was still BCC64X/Clang; Embarcadero's include layout has some MinGW-derived headers.
- The independent DNG SDK producer now sets `CXX_SCAN_FOR_MODULES OFF` because it does not use C++ modules. No compiler fallback or global include-path modification was added.
- The DNG SDK logical timestamp was advanced. **[not verified]** A new native compile must show whether the missing include is limited to scanning or persists in actual object compilation.

## DNG SDK variant-specific dependency resolution

- The operator's first `dng-sdk@1.7.1.2802` Debug configure stopped after compiler ABI detection with `Could not find dng_jpeg using the following names: jpeg, libjpeg`.
- Cross-checked the installed library naming contract already used by Skia: `libjpeg.lib` / `libjpegd.lib` for JPEG and `libz.lib` / `libzd.lib` for zlib. The DNG adapter now requires these exact per-variant import files, rather than assuming `find_library` resolves the Debug postfix.
- Advanced the DNG SDK logical timestamp to invalidate the previous producer source scope. **[not verified]** A follow-up Windows configure and native DLL build are still pending.

## Adobe DNG SDK 1.7.1 Build 2802 as a managed producer

- Registered `dng-sdk@1.7.1.2802` as a separate, versioned BuildEngine package for BCC64X Release and Debug, with a pinned revision of the DNG SDK source mirror.
- The producer uses a BuildEngine-owned CMake adapter, a shared DLL/import-library contract, managed zlib 1.4, libjpeg-turbo 3.2.1 and libjxl 0.13.0 dependencies, and the original Adobe DNG SDK license. Its license signal is yellow; this is **not an OSI-approved open-source license**.
- The SDK source version is verified in its header macros as DNG SDK 1.7.1 Build 2802. The source mirror is third-party maintained rather than Adobe controlled.
- The upstream Meson recipe is Linux-oriented and produces a static library. It is used as source-list evidence, not as evidence that the new Windows DLL has already built.

## Skia 153: remove embedded DNG source and keep RAW decoding

- Skia 153 now directly depends on `dng-sdk@1.7.1.2802`.
- A version-pinned GN patch selects a `system("dng_sdk")` consumer with managed header and DLL import-library paths; `skia_use_dng_sdk=true` remains enabled, and `SK_DNG_VERSION=0x01070100` identifies the new SDK API generation.
- Removed the previous Skia-side Android DNG Gitiles archive download, extraction, `dng_pthread.cpp` source requirement, and failed `std::auto_ptr` patch actions from the active BuildEngine XML.
- The Skia external-dependency manifest has **18 external components** and only **four remaining declared bundled components**: D3D12MemoryAllocator, SPIRV-Headers, SPIRV-Tools, and glslang.

## SDL3 GameInput native ABI buffer fix

- SDL3 3.4.20 progressed through configuration and its PCH adjustment; both builds then reported E3851 in `SDL_gameinputjoystick.cpp:870` where the upstream GameInput code passes `bool*` to an API requiring `BOOL*`.
- A version-pinned patch replaces `SDL_stack_alloc(bool, ...)` with `SDL_stack_alloc(BOOL, ...)`. The change preserves the Windows GameInput backend while correcting the buffer's element width; pointer casts would be unsafe.
- The patch is checked and applied in the **single source phase**, before Debug and Release build in parallel. No other package, SDK, compiler identity or global runtime policy has been changed. **[not verified]** The corrected BCC64X build and final smoke await native execution.
- Catalog remains **81 distinct libraries / 116 versioned integrations**.

## SDL3 BCC64X C11 precompiled-header correction (17 November 2026)

- The SDL3 Release build reached Ninja after successful configuration but failed on many C translation units with BCC64X error E904: the generated PCH had C11 enabled while the consuming translation units did not. The root is SDL3's upstream `target_precompile_headers(SDL3-shared ...)` configuration, not DirectX and not separate source failures.
- The package adapter now sets `DISABLE_PRECOMPILE_HEADERS TRUE` **only for the `SDL3-shared` target** after loading the upstream subdirectory. Sources, dynamic runtime, DLL, and functional subsystem switches are unchanged; no modifications to other packages or global toolchain.
- **[not verified]** The subsequent native Debug/Release compilation, install artifact naming, and consumer smoke have not yet been observed.

## Safe live-catalog optimization

- BuildEngine-Common now compares the complete bytes of `admin/build-libraries.xml` on catalog access, caches the validated parsed catalog by production path and reparses only when content changes. Changes with identical file size or timestamps are detected.
- A read or parse failure is reported rather than silently serving an obsolete catalog. Installed package and SBOM status remain live and are not frozen in the catalog snapshot.
- No HTTP thread pool, new background worker, or cross-request package cache has been introduced. This is the limited, measurable first optimization step, keeping the existing Server/Common responsibility boundary.
- **[not verified]** Native BCC64X compilation, live-update regression and latency benchmark are pending.

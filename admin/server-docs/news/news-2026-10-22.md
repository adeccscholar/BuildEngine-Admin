## From isolated examples to a unified test repository

On 22 October, BuildEngine began moving larger consumer applications out of the engine's original test tree and into the dedicated **BuildEngine-Tests** repository. The initial migration included PDFium common rendering components, a native VCL PDF viewer, an SDL2 PDF consumer, QPDF image extraction, and the existing CompareTest program. A shared CMake entry point and BuildEngine bootstrap connected these programs to the installed libraries instead of privately building another dependency stack.

This established a deliberate two-level testing structure. A library's small smoke test remains with its package contract and verifies its build, link and runtime interface. More substantial programs belong in **BuildEngine-Tests**, where they can combine several published dependencies, graphical interfaces, database services and real application workflows.

## The following days

On 23 October, the structure gained deterministic QPDF image-extraction regression fixtures, a Skia showcase and the VCL demonstration. On 25 October, further tests migrated from **DeckKernel**, including MSSQL and PostgreSQL consumers and OpenXLSX processing. Additional database, graphics and parallelism experiments followed in the same independent test structure.

This was a significant architectural step: testing no longer meant merely compiling examples inside the core repository. It became a set of consumer applications deliberately built **against the packages produced by the BCC64X BuildEngine**.

## Tensor Nebula becomes a native OpenGL 3.3 wave observatory

The initial 72 by 44 SDL rectangle grid has been replaced with a real GPU presentation pipeline. The new independent BuildEngine-Tests project computes one authoritative xtensor scalar field and uploads it as a native R32F texture through the managed Mesa OpenGL 26.2.1, GLEW 2.3.1 and SDL2 stack. Its user interface uses the already managed official ImGui SDL2/OpenGL3 DLL instead of introducing a second rendering adapter.

Four physical modes are available: two coherent sources, three-source interference, separable standing waves, and a Gaussian-modulated pulse. The user can choose a 512 by 288, 768 by 432 or 1024 by 576 tensor resolution; visualization options include cinematic exposure, luminous diffusion, isolines, relief shading and a **real depth-tested 3D heightfield** with orbit controls. xsimd evaluates genuine block reductions for mean and energy; xtl optional values represent missing or valid scientific probes.

The shared OpenGLShowcase preserves **F1 About** and **F11 reversible fullscreen**. The application provides an independently executable headless numerical verifier and an opt-in desktop OpenGL verifier. A screenshot command saves actual rendered GPU bytes into BMP without treating generated concept artwork as native evidence. The showcase description includes mathematical MathJax models, Mermaid architecture and dependency diagrams, and individually copyable one-line CMake commands for Release and Debug. Gallery and desktop concept SVGs were revised, with explicit generated-concept provenance.

**Verification:** the upgrade is committed source and documentation, **[not verified]** with a BCC64X application build or native GPU output. The successful 141-library FSM does not independently establish runtime acceptance of this newly upgraded showcase.

BuildEngine now attempts the first managed Windows Mesa GPU path without abandoning Softpipe. Mesa 26.2.1 retains the original `softpipe` renderer and native test/installation/consumer checks, while an experimental `d3d12` Gallium driver has been added to its Meson driver selection. A new declarative Microsoft DirectX-Headers 1.619.1 library source/build contract has been introduced with Release/Debug variants, original upstream native and GoogleTest test suites, version-pinned GoogleTest 1.18.0 reuse, installed pkg-config/CMake metadata, and a dedicated BCC64X D3D12 consumer smoke. The catalog now contains one additional declared logical library beyond its earlier 105-library snapshot; installed/ready status cannot be inferred from declaration alone.



Tensor Nebula now requests `softpipe`, `d3d12`, or `zink` from the actual Mesa WGL runtime, with restart-on-selection, optional Intel/NVIDIA D3D12 adapter preference, and explicit `GL_VENDOR`/`GL_RENDERER`/version reporting. The `--verify-gl` path rejects recognized software-renderer fallback when GPU mode was requested. Zink remains unbuilt: a managed Vulkan Loader 1.4.368 consumer and existing Vulkan-Headers CMake adapter have been prepared, but full upstream Vulkan Loader tests need an additional managed Microsoft Detours source dependency and complete native verification.

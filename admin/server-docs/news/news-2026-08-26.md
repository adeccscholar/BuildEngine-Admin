## Why OpenSSL changed the rules

The integration work moved from smaller CMake-oriented packages toward **OpenSSL**. The OpenSSL integration introduced a build contract using **GNU Make (`gmake`) and Perl**, followed by BCC64X source preparation and Windows-specific corrections. Upstream OpenSSL does not become a reproducible native dependency merely by declaring a version number: its source generator, command-line tools, target policies and compiler environment are part of the build.

The same day's commits expanded the **versioned library dependency contract**. Those relationships would become necessary for the later FSM: a package cannot independently advance to a meaningful readiness state if its required native dependencies are unaccounted for.

## Compatibility improvements

OpenSSL needed fixes for Perl invocation, the Windows `MemoryBarrier` path and other source adaptations. libarchive also required another round of validated Windows/Clang compatibility patching. These were early reminders that the interesting work was often in the integration boundary, not in the upstream C++ syntax.

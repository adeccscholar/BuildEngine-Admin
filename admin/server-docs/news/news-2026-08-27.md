## OpenSSL needs its own assembly bootstrap

NASM was introduced as a managed bootstrap tool for the Windows x64 OpenSSL uplink shim. The purpose was to stop depending on whichever assembler might happen to be installed on a developer machine, making the build definition more reproducible.

This was part of a broader lesson: a declared library version is not reproducible unless its helper tools and generated objects are controlled as well. The same day also records the removal of a zstd static-library product, showing that a registered output was not automatically kept merely because an earlier configuration had offered it.

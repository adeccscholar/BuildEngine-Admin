## Rebuilds, repairs and resets

The development record for 29 August does not read like a tidy release announcement. Repeated **curl repairs**, rebuild changes, a blocking integration issue, and an explicit **error/reset** appear alongside two libzip commits. The day illustrates why the BuildEngine objective had to go beyond compiling a library once: an upstream build, installed library, published artifact and independent consumer must agree on version and runtime dependencies.

There is no credible reason to turn these repair commits into an uninterrupted PASS narrative. The correct historical statement is that the source and build contracts were iterated, errors were encountered and the integration was reworked.

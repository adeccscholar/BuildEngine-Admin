## Before the repositories: a feasibility study

BuildEngine did not begin with the present library catalog. During August 2026, the initial **C++Builder 13 / BCC64X** feasibility work examined approximately **20 C and C++ libraries over roughly ten days**, according to the project [story](/manual/story.md). The purpose was not merely to provide precompiled libraries *for* C++Builder. It was to find out whether **C++Builder 13 itself could compile upstream libraries** using its modern Clang/LLVM-based BCC64X toolchain, rather than quietly falling back to MSVC or another compiler.

These roughly 20 investigated libraries were **feasibility cases**, not 20 registered BuildEngine packages. Their individual experiment dates are not established by the new repository history. This entry records that earlier August phase retrospectively rather than inventing a precise start date.

## 24 August: a deliberately small starting contract

The versioned Admin repository was initialized on **24 August 2026**. Its initial **schema 3** `build-libraries.xml` declared exactly **one library: pugiXML 1.16**. Later that day the contract advanced to **schema 4** and gained **nlohmann-json 3.12.0**, for a total of **two registered libraries**. This is the first directly verifiable inventory in the new repository, not a count of completed builds.

The initial administration structure already separated the engine from declarative library, tool, CMake, schema, and smoke-test definitions. That distinction mattered: the aim was not to hard-code a workflow for each tested library, but to describe reusable integration procedures in validated data.

The early architecture was still evolving. The eventual **library-centric finite-state machine (FSM)** should not be projected backward as though every current state and invariant had already been implemented on the initial day.

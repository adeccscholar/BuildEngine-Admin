# BuildEngine News — 2026-11-20

## Native smoke acceptance: three interface libraries

The operator-reported BuildEngine FSM confirms **PASS** for `hnswlib 0.9.0`, `miniaudio 0.11.26` and `libigl 2.6.4` Release consumer smokes and their respective `ready` transitions. These results are run evidence, not a claim of comprehensive performance benchmarking or security certification.

The consumer tests were aligned with the canonical smoke protocol described in `admin/smokes/README.md`: `SMOKE|CHECK|<id>|PASS/FAIL|<detail>` and exactly one `SMOKE|RESULT|PASS/FAIL|<detail>`. An earlier shared CMake C++23 dependency scanning pass failed before compilation; the BuildEngine BCC64X toolchain now disables automatic module scanning for non-module consumers and retains the Clang/EMBT compiler identity. This choice must be revisited for actual C++ modules.

The canonical `admin/build-libraries.xml` now includes three more versioned library registrations. The intended catalog size is **91 distinct library IDs and 126 versioned records** (previously 88 and 123), subject to a successful local catalog/schema parse.

| Package | Version | Source and build contract | Acceptance |

| [Jolt Physics](https://github.com/jrouwe/JoltPhysics/releases/tag/v5.7.0) | 5.7.0 | CMake project at `Build/`, shared CPU-oriented core, optional compute backends and samples disabled, IPO disabled | BCC64X shared export and ABI validation, installed runtime factory consumer |

The new consumers deliberately emit the same structured CHECK/RESULT protocol as the existing catalog. Source downloads, native compilation, installation, symbol export checks, consumer execution, per-version SBOM/license verification and archive SHA-256 verification **have not yet passed in the current evidence**. The upstream source archive bytes were not available for independent security inspection in this environment. Registration does not mean installed or security-approved.

For details, see `admin/docs/packages/zxing-cpp/3.1.1/migration.md`, `admin/docs/packages/recastnavigation/1.6.0/migration.md`, and `admin/docs/packages/jolt-physics/5.7.0/migration.md`.

No database schema migration is required for these source-only catalog additions. All changes were committed directly to `main`.

## Four interactive discovery showcases added to BuildEngine-Tests

The separate `adeccscholar/BuildEngine-Tests` repository now contains four new **native, interactive Windows C++23** showcase projects using the existing SDL2 + Dear ImGui presentation adapter. Each has a distinct application, reproducible per-project CMake configuration, a headless `--verify` CTest target and a server-readable `showcase.json` manifest.

- **[Vector Galaxy — The Shape of Similarity](/showcase/graphics/vector-galaxy/):** an 851-star mathematical nebula in which hnswlib performs true feature-vector nearest-neighbour search and libigl/Eigen compute vertex normals of the displayed heightfield. Live query controls change the highlighted results.
- **[Barcode Signal Lab — Decode the Invisible](/showcase/graphics/barcode-signal-lab/):** the application synthesizes standards-based EAN-13 bars independently and decodes their grayscale pixels using the native ZXing-C++ reader DLL; an offline round-trip CTest guards against merely decorative barcode graphics.
- **[Navigation Reactor — Terrain Intelligence](/showcase/graphics/navigation-reactor/):** a live Recast Navigation rasterization laboratory. Adjusting the permitted agent slope and terrain relief reruns the real `rcMarkWalkableTriangles` and `rcRasterizeTriangles` algorithms and displays the resulting heightfield spans.
- **[Pulse Engine — The Shape of Sound](/showcase/graphics/pulse-engine/):** a real miniaudio PCM synthesizer with sine, square, triangle and sawtooth oscillators, a luminous visual waveform, pitch and gain controls, and opt-in audible device playback.

All three register `status: "not-verified"`. They must **not** be announced as successfully compiled, visually inspected or performance-tested until the operator provides real Windows BCC64X execution evidence. The last observed Jolt Physics consumer still failed at runtime, so no Jolt-enabled showcase is claimed ready.

The showcase descriptions, controls, dependencies, build commands, license evidence and declared SBOM scope have been documented in English and linked from [the Server showcase guide](/manual/showcases.md). The central Server automatically discovers those files in the existing tests workspace; no new HTTP route or server executable change is necessary.
